# 前端编码代理约定

适用于 `src/`，同时遵守[根目录约定](../AGENTS.md)。先读 [CONTEXT.md](../CONTEXT.md)、[状态归属](../docs/architecture.md)，改通讯时再读[协议清单](../docs/protocol.md)。

## 模块和运行约定

- 使用现有 Vue 2 单文件组件和 Vuex 3，不在日常修复中引入 Vue 3/Pinia 或更换构建工具。
- `store/modules/players.js` 管座位及角色等状态；`session.js` 管会话、投票和聊天；`lobby.js` 管大厅；`quickWake.js` 管定向唤醒。根 store 管剧本和魔典偏好等。
- `store/socket.js` 包含 `LiveSession`、`LiveLobby` 和 mutation 到网络发送的桥接。新增 mutation 不代表网络同步已自动完成，须检查订阅及接收端。
- `src/logic/` 中已有可复用规则优先复用。DOM、交互状态与共享业务状态分别放在当前适合的位置，不机械抽取只有一个简单调用点的包装。

## 共享状态与副作用

- 新的共享状态更新通过 mutation/action；局部 UI 状态可留在组件。历史直接赋值属于现状，不作为新代码示例。
- 保持 Vue 2 响应式更新方式：新增对象属性或更换集合时使用项目已有 `Vue.set`、替换对象/数组等方式；Map/Set 不能假定原地修改会自动更新界面。
- 保留插件顺序 `persistence → quickWakePersistence → socket`：先恢复本地会话和唤醒上下文，再建立连接。修改顺序必须有恢复行为测试。
- 收到网络消息提交 mutation 时，检查 host/player 分支及来源标记，避免订阅器再次发出同一消息造成循环。
- `isSpectator=true` 表示非说书人，包含已落座玩家；`claimedSeat=-1` 才是未落座。座位下标和稳定 `playerId` 不可互换。
- 房间、身份切换后，旧连接事件和 outbox 不能写入或发往新上下文。不要将旧目标座位上的新玩家当成原收件人。
- 关闭/重连/组件销毁时清理本次创建的定时器、事件、订阅和媒体资源。

## 隐私和协议

- 公开 `gs` 是过滤后的投影，不要直接序列化完整 players/store。角色、盲抽角色池和私密提醒的可见性取决于定向投递、公开旅行者或复盘等路径。
- 角色分配、私聊和魔典展示沿用现有定向行为；不能把“本地界面没显示”当成数据未下发的证明。
- 快速唤醒使用 `quickWake*` 专用协议，不经普通 `direct` 或广播发送保留命令。
- `quickWakeAccepted` 只确认服务端接收；玩家 receipt 后才是送达。重试沿用同一 ID，回复关联 `wakeId`，不能根据发送成功就清除待回复状态。
- `stSecret` 是浏览器凭证，`playerId` 是公开标识；不要将凭证加入游戏快照、错误提示或日志。

## 持久化与连接配置

- `persistence.js` 仍使用多种历史键；`safeStorage.js` 只能在存储失败时维持当前内存会话，不保证刷新后恢复。
- 快速唤醒历史按房间和本地玩家隔离，预设跨房间；切换上下文必须先读取旧保存内容，再写入，不能用初始化空状态覆盖它。
- 调整键名/数据形状时考虑旧存储、非法 JSON、配额耗尽及读取失败；不要以清空所有 localStorage 代替迁移。
- 默认 API/WS 同源；运行时 `window.__TS_*` 覆盖值必须在 store 初始化前提供。部分资源接口仍是相对路径，见部署和协议文档，不能宣称分域只需改一个变量即可。

## 验证与文档

运行 `npm run lint-ci`、`npm run build`。涉及唤醒、状态恢复、模板或 socket 时再运行 `npm run test:quick-wake`；跨端协议按根约定执行服务器测试。现有状态测试会提取组件脚本，不能替代真实浏览器布局、键盘及多客户端验收。

更新协议或状态时同步相应文档与测试；超出任务范围的整理写入 [TODO.md](../TODO.md)，不附带大规模重排或资源修改。
