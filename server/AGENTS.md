# 后端编码代理约定

适用于 `server/`，同时遵守[根目录约定](../AGENTS.md)。先读[后端说明](README.md)、[协议清单](../docs/protocol.md)和[状态归属](../docs/architecture.md)。

## 当前结构

- Node.js CommonJS，入口 `index.js`，根目录安装依赖，推荐 Node 22。
- Express HTTP 与 ws 共用同一个 HTTP server。没有数据库；房间、身份绑定、公开快照和唤醒记录在单进程内存中，头像写入 `AVATAR_DIR`。
- 主要游戏规则与私密角色状态仍由说书人前端编排；后端负责部分校验、投递及状态协调，不能称为纯无状态中继。
- 当前普通消息有通用转发路径，授权并不完整。新代码不能复制“仅检查前端按钮”作为权限模型，也不能把计划中的校验写成已实现。

## 消息和身份

- 保持现有数组帧 `[command, params, feedback?]` 以及 HTTP 响应形状；变更需同时更新发送端、接收端、协议文档和行为测试。
- `playerId` 是公开标识，`auth` 使用浏览器持有的 `stSecret`。服务端身份以当前连接及房间绑定为依据，不信任消息自报的发送者 ID。
- 新的敏感操作须核对该连接仍是房间当前 host 或对应 player 的当前连接；不能只检查路径中 `/host` 或旧连接元数据。
- 对外部输入检查形状、类型和长度后再解构或使用；未知/错误输入不应抛出未处理异常终止进程。
- `direct` 只决定投递对象；feedback、发送到 socket 与接收者实际收到/处理是不同层次，不扩大确认语义。
- 快速唤醒保留命令只能走专用处理路径；维持目标身份、房间、座位名单、ID 冲突和回复归属校验，禁止经普通 direct/广播注入。
- 快速唤醒重试沿用 ID，服务端接收确认不等于玩家送达；未回复记录与已回复记录回收规则不同。

## 生命周期与资源

- 仅说书人建房。拒绝加入不存在房间的玩家时不能创建幽灵房间。
- 没有 host 且 `players.size===0` 才进入空房回收宽限期；host 离开但仍有玩家不是空房。重连要取消对应回收；主动解散立即移除并正常关闭玩家连接。
- 替换连接后的旧 close 事件不得删除新连接。处理过期连接和鉴权失败连接时检查当前成员资格。
- `lastGs` 当前仅缓存说书人完整普通广播；direct 和 lightweight 不刷新它。不能将其当成增量一致、持久或完整私密游戏存档。
- 新测试自启动服务应使用动态端口和临时头像目录，等待真实就绪，捕获启动错误，finally 关闭连接、等待子进程退出并移除临时目录。
- 修改上传或外部抓取时关注归属校验、可接受格式、大小、超时和重定向；现有缺口见 [TODO.md](../TODO.md)，不暗示已经修复。

## 验证

从根目录执行：

```sh
npm run check:server
npm run test:quick-wake
npm run test:room-lifecycle
```

`node server/test-ws.js` 另需先启动独立的 3000 端口服务，见[测试指南](../docs/testing.md)。新测试优先通过真实 HTTP/WS 接口验证行为，不能只检查内部 Map 或用无条件 true 代表成功。合理控制计时容差；负向检查须结合服务可用或有序成功响应。

修改运行配置同步本目录 README；变更协议、状态或测试入口同步对应文档。发现范围外缺陷写入 TODO 并保留证据，不通过弱化测试制造绿灯。
